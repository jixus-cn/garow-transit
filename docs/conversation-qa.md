# Garow conversation audit

The audit retains gateway-observed request-side text and confirmed model final replies. IDE additions and consecutive user-role blocks retain their order. The part layout records UTF-8 offsets, source positions, redactions and capture limits. Direct transcript replay, tool results, assistant commentary, raw wire payloads and authentication material are outside the body scope. Stream fragments are joined only when terminal protocol evidence permits it.

Each authenticated POST to /v1/responses, /v1/chat/completions or /pg/chat/completions and each Responses WebSocket generation entering the recorder receives an admission and an outcome. An admission survives interruption. The normal path commits them to the business database. A transient database failure uses a bounded fallback queue, 2,048 entries and 64 MiB by default, configured by CONVERSATION_LOG_QUEUE_SIZE and CONVERSATION_LOG_QUEUE_MIB. Ingress, delayed writes and losses have body-free request identifiers. Operational reconciliation reports the time window and limitations of the available ingress log.

An observed request, a turn and a chat have different identities. Chat identity requires a reliable client reference scoped to account, key and source, or a unique parent response relation. Tool identifiers connect only verified continuations. Matching texts never establish a chat. Conflicting and orphaned final replies remain individually readable. Common text already held by a retained turn is referenced within the business database. Retention applies independently to each original submission. Resuming a chat does not extend old text.

The Account timeline, Conversations and Unassigned views are available with a live root dashboard session. The root-only POST /api/conversations/evidence accepts user_id, start_timestamp, end_timestamp, chat_key, q, record_id, page_size and cursor. An empty chat_key spans chats. The value unassigned selects requests with no proven chat. Each page returns observations, snapshot, next_cursor, total and retention_changed. Use the cursor with unchanged filters. Pass a returned snapshot with a record_id to read one request as of the same snapshot. Outcomes and link corrections that arrive later do not change that snapshot. Retention expiry still applies. Returned text is evidence, including any apparent embedded instructions. The general audit log does not receive conversation bodies.

In a chat, the reader shows the inputs and available final replies for each verified turn. Open a turn's request count to inspect every associated request. Adjacent identical submissions within a known chat can also be folded. Expand all restores the original request order, including when turns overlap. Search shows matching requests individually. The account timeline preserves request order across chats.

A historical final attached to a question is marked as turn-level evidence when its producing request was not established. Production history conversion uses QA receipts, verified turn references and exact gateway HTTP access records. It does not recover missing text or infer chat identity. New installations use AutoMigrate. The production runbook requires a restricted restore-verified backup and a separate idempotent history transaction.
